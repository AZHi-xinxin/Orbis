# Operit 聊天导入兼容

导入入口按聊天结构识别，不再仅允许一个固定版本号。当前已验证旧版 `content` 正文结构和新版 `sections` 分段结构；新版本若继续使用这些结构，可以继续导入。未知版本会在预览中提醒核对。这不等于承诺所有过去和未来格式均可完整迁移。

## 兼容规则

- 必须是带 `archiveType: operit_chat_archive`、正整数 `formatVersion` 和 `chats` 数组的聊天归档。原始数据库、CSV、无标识列表等不是此入口的格式。
- `content` 读取原文；`sections` 依顺序读取正文、思考、工具调用/结果和状态。明确的思考段可折叠；正文中的字面思考标签不会被误判。
- 目录、排序、额外应用元数据不阻塞读取，也不会被装进目标应用的设置。额外字段仍接受 JSON 完整性、重复键、编码、深度和容量校验。
- 陌生内容段或没有可用原文的工具段，保留为原始 JSON 结构文字并在预览计数；历史工具永远不执行。附件只保留文字引用，不读取外部路径或下载媒体。
- 正文缺失、两种正文表达冲突、未知发言角色、选中的重生成分支缺失等关键问题会明确停止，不会默默填空或随便挑一条回答。
- 仅导入导出时选中的回答，内部摘要跳过并计数。身份、人设、密钥、权限和工作区配置不迁移。请始终保留原件。
- 超长消息可沿已有内容段拆成连续历史记录，原文和顺序保持，首条来源 ID 不变；重复导入仍跳过。单个内容段本身超限时不截断，整个相应会话报告失败。数据库的单条写入上限不放宽。
- 预览和实际导入使用同一解析器。提交前核对文件指纹并冻结输入；只追加选择的会话，已有聊天不被覆盖。格式改变不重新生成来源 ID，因此旧版/新版重复导出也不会悄悄覆盖之前的导入。

## 验证边界

旧版和新版结构、模拟后续版本、额外字段、未知内容段、分支选择、无损分段、重复导入、错误与取消等由合成回归覆盖。真实提供的新版归档另做本机私密对账，原文不进入仓库测试夹具。

公共源码中的旧格式定义参考 [OperitChatArchive.kt](https://github.com/AAswordman/Operit/blob/27d3a458eeaa47ffc1d83f3078032a030841f47c/app/src/main/java/com/ai/assistance/operit/data/model/OperitChatArchive.kt)；新版结构依据实际提供的导出文件核对。未来若改变核心聊天含义或变成另一种封装，仍可能需要适配；不会以“导入成功”掩盖内容丢失。
