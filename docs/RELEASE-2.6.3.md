# Orbis 2.6.3

本版修复旧安卓系统上更新时误报“安装包签名与当前应用不一致”的问题。沿用原发布签名，不变更聊天格式、数据库结构或模型配置。

## 遇到签名不一致，请先不要卸载

2.6.1／2.6.2 的更新器在 Android 9／10 上可能没有读到下载包证书，因而误报签名不一致；已在 Android 10 实机确认这个原因。2.6.3 会正确请求系统收集证书，并继续严格核对当前签名，不会跳过校验。

旧更新器在安装新版之前仍会拦截，**受影响用户需要从 GitHub 手动下载修复版，保留原应用直接覆盖一次**：

1. 先分别备份重要聊天、花园、书库及其他独立数据。
2. 在浏览器打开 [v2.6.3 发布页](https://github.com/AZHi-xinxin/Orbis/releases/tag/v2.6.3)，下载适合设备的 APK。
3. 从下载列表打开文件，按系统提示允许该来源安装，再确认更新。不要卸载或清除数据。
4. 打开原 Orbis，核对版本 2.6.3 及原来的聊天、设置。后续更高正式版再使用应用内更新。

无需电脑或调试工具。2.6.0 也可直接覆盖升级，不必逐版安装。若系统安装器本身仍报签名冲突，请停止并核对来源，不要绕过。

## 安装包

| 文件 | 适用设备 |
| --- | --- |
| `Orbis-2.6.3-arm64-v8a.apk` | 大多数近年的 Android 手机，优先选择 |
| `Orbis-2.6.3-x86_64.apk` | 对应架构设备或模拟器 |
| `Orbis-2.6.3-universal.apk` | 包含上述两种架构；不包含 32 位 ARM |

最低 Android 8.0（API 26）；版本代码 `236`；正式包名 `org.orbis.agent`。Dev 是独立应用，不能用正式 APK 覆盖或自动迁移数据。

## 修复与边界

- 同时使用旧、新证书查询标志，兼容旧安卓的 APK 证书收集流程。
- “无法读取证书”和“实际签名不同”分别提示，两种情况都阻止安装。
- 仍检查官方来源、下载大小、SHA-256、包名、当前签名集合、更高版本代码和系统要求；没有关闭任何校验。
- 历史 2.6.2 发布包和标签不替换。聊天迁移、引用收藏、时间信息及朗读修复继续保留，见 [2.6.2 说明](RELEASE-2.6.2.md)。
- Android 10 证书读取已实机复现验证；从修复版到下一更高正式版的应用内下载、系统授权与覆盖安装完整流程仍待后续验收。不要把证书读取通过或手动覆盖成功等同于完整自更新通过。
