# Orbis 2.6.13 — 正式包准备

正式候选版本代码 `277`，高于 2.6.12 的 `275` 和旧 2.6.13-rc.1 的 `276`。公开安装包以 GitHub Releases 实际上传的同签名附件为准；本文不是已经发布的证明。旧标签和下载文件保留。

## 本次交付范围（2026-10-25）

本次正式包以维护者已经验收的 Dev120 源码为基础，包含下面的 Dev119 修复与身体状态自动注入。未合入 Dev121/122 的侧栏、主题、图片记忆、健康记录等待验收功能。

- **身体状态自动带入本轮**：先结算本轮人类消息引起的变化，再把 AI 已定义的指标和值带入同轮请求。AI 无须反复调用查询工具才能获知当前状态；工具续轮复用本轮快照，不重复触发事件。不会把这段宿主资料当成人类新发言供 ST 检索或采集。
- **保留稳定请求前缀**：动态身体状态与动态召回资料放在后部，减少对长前缀的改动；不承诺所有服务商固定的缓存命中率。
- **升级兼容**：正式包沿用 `org.orbis.agent` 和原发布签名。主包与 Rescue 都提供 arm64-v8a、x86_64 和 universal；Rescue 是同包名的备用入口版本，不是插件。

维护者已在 Dev119 验收切档、重开、聊天、Rikkahub 导入、世界书和整理；在 Dev120 验收本轮身体状态直接读入及聊天。公开优化成品的构建、签名、实际推理和附件回读须另外记录，不以这些开发包反馈替代。

正式发布后，2.6.12 等正常正式版本可通过应用内检查发现新版本；旧 `-rc.1` 版本名不符合当前更新器解析规则，需要从发布页手动下载同签名包覆盖。Dev 包名独立，不会被正式版覆盖。

## Dev119 修复进展（2026-10-25）

以下更新覆盖早期候选的验证状态。开发包 `2.6.13-orbis-dev.119-memory-fix` 已完成完整 Gradle debug 构建、同签名覆盖及真机标准/独立记忆切换、退出重开、聊天收发验收；尚未创建新的公开 Release。

- **记忆切档闪退**：ONNX Runtime Android 从 `1.23.2` 更新到 `1.24.3`，解决已复现的 Android 16 / 部分 ARM64 芯片错误选择 SME2 指令导致的原生崩溃及启动循环。同一真实设备上的隔离测试运行实际模型，并覆盖切档、服务重启与原记忆保留。
- **记忆缓存布局**：固定记忆保留稳定前缀，动态召回资料后置。Chat Completions 使用当前用户消息前的独立资料段，保持人类原文不变；ST 检索、采集不会把召回资料当成人类新发言。只处理宿主明确标记的请求副本，不按文字标记删改聊天。工具续轮沿用同轮选择；记忆暂停、删除和轻量档仍能停止投影。
- **Rikkahub 大记录导入**：分块读取超过 Android CursorWindow 的消息，再按目标记录预算拆分保留内容，避免把长工具历史误报为格式不兼容。历史工具只作文字导入，不执行。原备份没有附件文件时仍不能凭空恢复附件。
- **世界书选择保存**：会话入口使用独立字段与增量修改保存；旧聊天写入不会覆盖刚选的世界书/模式，助手默认与当前会话入口有明确区分。
- **整理被旧断点阻塞**：对同属主、已验证的不兼容断点，先完整保全并读回，再释放活动位置。失败或并发变更时保留现场，继续保留自动任务安全暂停，不重放工具。
- **身体层及已有交互改动**：名称旁爱心入口、状态卡、私密维度与双方可见条件；AI 定义规则，系统按新的人类消息匹配和浓度自动计算，AI 负责暂停/修改/恢复。冷静词与反应可自定义，不预置个人规则。首次规则默认自动模式，兼容旧手动规则并提供设置提示。同步问卷返回聊天的路由修复、长文本兼容及通话上下文精简。

本轮验证：`ai` 479 项、`app` 5409 项 JVM 测试通过；4 个需额外私人档案的导入探针默认跳过。同一 ARM64 手机的 15 项记忆测试通过。四类模型协议使用实际序列化器验证；ST 侧使用合成导出请求验证三种上下文布局，网关 811 项通过、1 项 Windows ACL 专项在 Linux 跳过。

Rikkahub 实际备份已在隔离 Android 环境完成 8 窗口、9268 源消息的全量内容对账、重开与重复导入检查；3 个过长节点拆分后目标节点数增加 4，文本没有因此丢弃。世界书保存、断点冲突也有隔离 Android 回归。随后用户在正式手机上确认：Rikkahub 导入并打开、世界书开关保持并生效、聊天整理均正常。 身体长期历史、完整恢复与真实云缓存命中率对照也未全部完成；稳定请求前缀不能等同于固定命中百分比。

数据库升级到 `31`，不要强行降回只认识版本 `30` 的旧包。签名私钥、真实聊天备份、手机数据库及私人测试资料不进入仓库。本源码更新不包含生产 ST 部署。

## 早期 2.6.13 候选记录

下面保留初始候选的故障说明与当时验证边界；构建、运行库及开发包真机状态以以上 Dev119 进展为准。

## 续聊保存

已验证的一条故障路径是：旧续聊恢复副本与当前聊天代次不同，无法合并，却一直占据唯一的活动保存位置；后续新消息的副本写入与数据库提交准备都会被它拒绝，造成页面能继续聊、重新进入后新内容不见。

本版在会话初始化、尚无活动续聊写入时核对副本。有效但不兼容的旧副本先按内容摘要另存、同步和读回确认，再释放活动保存位置。失败则保留原副本；损坏、异主或仍有活动写入的副本不冒然移走。归档后保留自动任务安全暂停，不重跑旧工具、不凭归档推断旧工具成功。

保全副本随普通数据库备份导出/导入，保持内容摘要与窗口、助手身份检查。它不是可执行的活动记录，也不会直接覆盖当前聊天。此修复不保证找回已经从未落盘的消息，不会自动把冲突旧尾拼回主记录。

## 内部时间标签

人类消息的历史时刻仍只投影到模型请求，并明确说明不是用户正文、不应复述。输出端识别宿主生成的时间信封，处理流式未完成标签和跨文本分块，避免其原样出现在新 AI 回复里。

不会宽泛删除任意 XML、用户原始输入或工具结果，也不改写冻结的旧历史；模型复述普通人类文字不能仅凭 `user` 字样自动删除。这不是对任意模型永不复述后台信息的保证。

## 整合已有测试包修复

- ONNX Runtime 固定为 `1.23.2`，保留 JNI 需要的类与成员；release/rescue 都应用规则，保留成品 JNI 和全部原生库 16 KB 对齐检查工具。
- 兼容旧恢复记录省略的模型收据字段校验，不放宽内容或身份验证。
- 保留 DeepSeek 备份容器布局兼容和救援诊断改动。

## 验证边界与升级提醒

本轮完成定向生产源码编译（包括聊天服务接线），以及保存/恢复、历史分支、备份、时间投影和输出过滤的 JVM 回归；真实旧备份在只读、内存存储探针中验证了保全后新写入与重新读取，原件未改动。详细测试数以维护者本轮回执为准。

另将本轮新编译类与已有编译产物合并执行了 5308 项应用 JVM 测试：5304 项通过，4 项设置存储测试在 Windows 临时文件重命名处失败。移除本轮补丁类后，旧编译产物单独运行同一测试类仍出现相同 4 项失败。此对照不等于已解决该测试环境问题，也不等同于全量源码重新编译通过；发布前仍需在正式构建环境复核。
