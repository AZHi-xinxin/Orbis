# Orbis 2.6.13 — 源码候选

版本代码 `276`。本次先同步经过定向验证的修复源码，不创建正式发布标签或上传未经本轮验收的 APK。已有标签、下载资产和签名保持不变。

## 续聊保存

已验证的一条故障路径是：旧续聊恢复副本与当前聊天代次不同，无法合并，却一直占据唯一的活动保存位置；后续新消息的副本写入与数据库提交准备都会被它拒绝，造成页面能继续聊、重新进入后新内容不见。

本版在会话初始化、尚无活动续聊写入时核对副本。有效但不兼容的旧副本先按内容摘要另存、同步和读回确认，再释放活动保存位置。失败则保留原副本；损坏、异主或仍有活动写入的副本不冒然移走。归档后保留自动任务安全暂停，不重跑旧工具、不凭归档推断旧工具成功。

保全副本随普通数据库备份导出/导入，保持内容摘要与窗口、助手身份检查。它不是可执行的活动记录，也不会直接覆盖当前聊天。此修复不保证找回已经从未落盘的消息，不会自动把冲突旧尾拼回主记录。

## 内部时间标签

人类消息的历史时刻仍只投影到模型请求，并明确说明不是用户正文、不应复述。输出端识别宿主生成的时间信封，处理流式未完成标签和跨文本分块，避免其原样出现在新 AI 回复里。

不会宽泛删除任意 XML、用户原始输入或工具结果，也不改写冻结的旧历史；模型复述普通人类文字不能仅凭 `user` 字样自动删除。这不是对任意模型永不复述后台信息的保证。

## 整合已有测试包修复

- ONNX Runtime 固定为 `1.23.2`，保留 JNI 需要的类与成员；release/rescue 都应用规则，保留成品 JNI 和全部原生库 16 KB 对齐检查工具。
- 兼容旧恢复记录省略的模型收据字段校验，不放宽内容或身份验证。
- 保留 DeepSeek 备份容器布局兼容和救援诊断改动。

## 验证边界与升级提醒

本轮完成定向生产源码编译（包括聊天服务接线），以及保存/恢复、历史分支、备份、时间投影和输出过滤的 JVM 回归；真实旧备份在只读、内存存储探针中验证了保全后新写入与重新读取，原件未改动。详细测试数以维护者本轮回执为准。

另将本轮新编译类与已有编译产物合并执行了 5308 项应用 JVM 测试：5304 项通过，4 项设置存储测试在 Windows 临时文件重命名处失败。移除本轮补丁类后，旧编译产物单独运行同一测试类仍出现相同 4 项失败。此对照不等于已解决该测试环境问题，也不等同于全量源码重新编译通过；发布前仍需在正式构建环境复核。

**尚未完成本轮全量 Gradle 构建、优化成品 APK、Android 文件系统上的故障注入和受影响真机升级验收。** 工作站可用提交内存尚不满足既有完整构建门槛，因此不能把定向测试等同于可分发正式包。后续仍需按[发布签名与成品验收](RELEASE-SIGNING.md)完成这些步骤。

偶发 MCP HTTP 409 已有用户反馈自行恢复，但未据此宣称根因已修；本次保存缺陷与该错误分开处理。附件累积 HTTP 413、慢链路大型备份超时及自定义请求头作用范围等[既有未完成问题](RELEASE-2.6.12.md#必须保留的已知限制)不在本轮修复范围。

正式包产出后仍应先备份、核对同包名同签名，再覆盖升级；不要卸载、清数据或用旧版强行降级。含新保全副本的备份应使用支持本格式的版本恢复，旧版不能保证识别这些副本。
