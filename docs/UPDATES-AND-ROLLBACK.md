# 更新检查、安装与回退

自 2.6.1 起，在“系统设置 → 版本更新与回退”查看更新。入口使用本项目 `AZHi-xinxin/Orbis` 的 GitHub 正式 Releases，不使用上游 RikkaHub 的更新服务器，也不需要 GitHub 账号或令牌。最新版本检查用 `releases/latest`；历史列表用 `releases`。只获取公开版本号、说明和资产元数据，不向该接口发送聊天、书库或模型密钥。[GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)

自动检查最多每 24 小时一次，失败也计入间隔；用户可手动重新检查。提醒并不等于系统推送服务：不运行持续后台轮询，不自动下载、不静默安装。发布说明按纯文字展示，不加载其中的远程图片或执行 HTML。

下载进度在应用的更新弹窗中显示，不是系统下载管理器的后台通知任务。关闭弹窗会取消正在进行的下载；需要继续时请重新进入核对，不要把已下载部分当作完整安装包。

用户确认备份后才能下载适配本机架构的 APK。下载先核对 GitHub 资产摘要和可用的 `SHA256SUMS.txt`，两者都存在时必须一致；没有可用 SHA-256、下载大小不符或摘要不符时停止。随后核对 APK 包名、签名、最低系统要求和版本代码，只有同一正式包、相同签名且版本代码更高时才交给 Android 安装器。校验不能替代发布者来源审查；系统仍会进行安装验证。

安装使用应用私有缓存和只读 `FileProvider` URI，不使用公开可写下载文件作为已验证安装包。需要用户在系统中允许 Orbis 作为安装来源，并再次确认安装；打开系统安装界面不代表安装成功。[Android 安全文件共享](https://developer.android.com/training/secure-file-sharing/setup-sharing)

## Dev 与正式版

`org.orbis.agent.dev` 与正式版 `org.orbis.agent` 不是同一个应用。Dev 不自动检查正式版更新，也不会把正式 APK 当作覆盖更新；手动入口只提供正式发布信息和网页。它们不会自动共享或迁移应用数据。

## 2.6.1／2.6.2 在旧安卓上误报签名不一致

Android 9／10 的旧系统接口只在请求旧签名标志时收集 APK 证书。旧更新器仅请求新签名标志，可能得到空证书并误报“不一致”。已在 Android 10 对同一个已安装的官方 APK 复现，并验证同时请求两个标志可读到正确证书。2.6.3 修正此调用，仍只比较当前签名，无法读取证书时仍拒绝安装。

受影响用户需要手动覆盖一次，因为安装新版之前，仍是旧更新器在拦截：

1. 先分别导出并核对重要聊天、花园、书库等数据，保留原应用。
2. 用浏览器打开 [2.6.3 官方发布页](https://github.com/AZHi-xinxin/Orbis/releases/tag/v2.6.3)，下载适配手机的签名 APK，通常为 `Orbis-2.6.3-arm64-v8a.apk`。
3. 从下载列表打开 APK，按系统提示允许这个下载来源安装，并选择更新／安装；不要先卸载或清除数据。
4. 打开原来的 Orbis，确认版本为 2.6.3、聊天与设置仍在。以后更高正式版可再走应用内更新。

这个办法同样适用于其他受影响用户，不需要电脑调试。2.6.0 用户也可直接覆盖到修复版。若 **Android 系统安装器** 仍提示签名冲突，应停止并核对旧包来源、包名和证书；不要把所有签名错误都当作此次兼容问题，更不要卸载来绕过。

## 回退的真实限制

历史版本入口可查看说明与下载，但不是一键撤销。Android 使用 `versionCode` 阻止低版本普通覆盖安装。应用不会为回退卸载自己、清除数据或强制降级。[Android 版本管理](https://developer.android.com/studio/publish/versioning)

若官方发布标记为 `recovery`／`rollback` 的兼容恢复包，仍须同包名、同签名、版本代码高于已安装版，才能通过本应用检查后提交系统安装。回退旧代码也可能无法读取新数据格式，发布者必须另行验证；标记本身不是安全或兼容证明。

任何升级或恢复之前，请分别备份聊天、后花园、书库及其他重要独立数据。聊天 ZIP 不是整机或整个应用的镜像。不要为解决安装冲突先卸载或清空应用。

## 验收边界

策略测试使用合成发布元数据，覆盖来源、架构、哈希、版本、签名与回退限制；不会下载真实 APK 或操作设备。**2.6.1 发布时，真实发布包的端到端自更新仍待验收**：系统安装授权、真实签名包覆盖、取消下载、网络切换和数据兼容需要在可恢复的测试环境中另行实测，不能把源码接线与策略测试当作已经通过。

2.6.1 → 2.6.2 的 Android 10 实机应用内验收已发现上述证书读取误报。2.6.3 修复的是所有正式构建共享的更新器，不是更换发布签名。修复版到下一更高正式版的下载、安装来源授权、系统确认及保留数据完整流程仍待后续验收；手动覆盖成功不等于该流程已通过。
