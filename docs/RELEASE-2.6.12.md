# Orbis 2.6.12

本版汇总 2.6.11 之后的陪伴、语音、AI 配置、记忆与数据保全改动，不只是最后一轮修复。公开版版本代码为 `275`；安装包以 [GitHub 发布页](https://github.com/AZHi-xinxin/Orbis/releases)实际上传的签名附件为准。

下方区分已实现的代码范围、既有开发版验证和仍未解决的问题；这份说明本身不是新正式包构建、上传或覆盖验收成功的证明。

## 宠物与学习陪伴

- 宠物房间增加场景素材与多动作渐变，包括待机、亲近、迎接、进食、玩耍和休息；交互控件尽量避开动物和场景。采用二维姿态素材，不宣称实时三维运动。
- 接入可选 AI 反应，保留照料事件与日记。离开应用后按经过时间结算饱食、饮水和心情，不把关闭界面当作停止成长；这不代表后台持续运行模型请求。
- 寄养维持食水，心情缓慢下降；累计照料日可获得翻译次数奖励。换设备仍需恢复对应数据，不会凭空同步宠物状态。
- 学习区加入题库、不同题型练习、答题与错题记录、专注和统计，并提供相关 AI 工具入口。模型判题和建议不是人工核验答案。

## 语音台与通话

- 试听直接调用已配置的 TTS，再通过语音台处理；不再以已有音频试听代替真实生成链路。提供空间感、距离、滤镜、语速和音调等设置，也可关闭效果。
- 通话、语音条、朗读及其他接入统一播放链路的 TTS，沿用后台已保存的设置。一轮开始时固定提供商、基础语速与混音快照，之后调整供下一轮使用，不热改正在播放的 AudioSink。
- 去掉普通 TTS 不必要的固定 160 字短分段及人为片段间等待；仍遵守具体服务商与系统 TTS 的输入限制，不承诺所有文本只产生一次请求。
- 播放停滞时按状态结束故障播放器，下一次显式播放可重建；取消和拥有者校验拦住旧回调，不自动重播旧段。
- 挂断时各清理阶段独立执行，异步停止与最终状态收尾均纳入异常处理；没有确认采集和播放释放时，不将旧通话当作已完全停止而放行新通话。
- 保留真实通话及声学信息，去掉每轮普通聊天重复注入已挂断说明的路径。返回 Orbis 当前窗口的工具使用 Orbis 名称并区分请求与实际前台结果；仍受 Android 的后台启动和权限规则影响。

## AI 配置、观测和本机记忆

- AI 可检查和配置模型角色、TTS、MCP、工作区连接及备份目标，提出连接配置并试用受支持的检查入口。需要密钥时由人类填入；MCP 写入配置不等于自动开启，保存成功也不等于网络连接成功。
- 支持按已有许可继续操作，减少重复确认；不会替用户提供账号、密钥或保证任意第三方协议都能连接。外部 ST、星图或服务器不是使用普通 Orbis 的前提。
- AI 全局观测默认关闭。开启后以精简字段提供当前助手、窗口、模型、工具模型及相关交互统计；无刷新/删除事件时不额外报告这类事件。列表信息通过按需工具读取，不主动塞入所有窗口正文。
- 状态观察放在当前请求合适的位置，避免每轮不必要地改动长系统前缀；只替换自身标记。供应商是否命中缓存仍由其实现和请求决定。
- 增加可选的本机语义召回，以离线模型对符合条件的便签、记忆和压缩记录建立可重建缓存，改善同助手跨窗口衔接；遵守助手隔离、资源档位和自动带入设置。轻档不开自动带入，模型不因此自动上传文本到另一嵌入服务。
- 模型和运行时的固定版本、散列与许可索引见[离线记忆来源](OFFLINE-MEMORY-SOURCES.md)。向量缓存不是聊天原文备份，删缓存不能代替保全原件。

## 聊天保存、压缩和历史查询

- 改善历史切换与续聊持久化，数据库提交成功后才推进相应界面状态；旧暂停队列不应阻止新的人类输入，也不擅自重放不明状态的历史工具。
- 修正通话结束后同轮压缩将摘要误标为通话内容、导致摘要折叠和恢复校验失败的路径。
- 对已受影响记录，仅在助手、窗口、压缩代次、前缀和旧尾内容等严格证明通过后校正摘要的两个通话标签；通过并发校验及读回确认收敛旧恢复副本。不拿旧尾覆盖更完整的新回复，不以删除日志或放宽校验掩盖冲突。
- 新增当前窗口的非选中分支和删除记录查询工具。缓存与 Room 同库提交并绑定助手/窗口；压缩时同步清理超出保留范围的记录，返回的历史引用不会作为工具再次执行。
- 数据库由 schema 29 升至 30。此缓存不是全局聊天搜索，也不能找回功能启用前从未保存的删除内容。

## 本地及服务器备份

- 加入本地检查点、恢复入口、连续备份和 AI 配置通道。AI 可以依照人类提供的服务器信息绑定、检查、请求保存和恢复，不要求维护者代填每位用户的地址。
- 固定云端存档使用唯一临时对象，完成读回校验后再按代次原子替换；上传或发布失败保留旧固定存档，不降级为不安全的直接覆盖。需要支持该发布协议的服务端；任意普通 WebDAV 目录不等于已经具备此能力。
- 手动立即保存使用独立的新任务，不被旧自动任务的指数退避排队替代；保留并发门禁，记录实际所处阶段和失败类型。
- “已排队”“连接检测成功”“正在上传”和“已校验完成”是不同状态。只有完成回执才能证明该次新存档已发布。
- 新装后可从已配置的可用目标拉取外部备份；首次恢复仍需可用的连接信息。卸载会影响应用私有数据，不能保证仅靠本机缓存自动找回全部内容。工作区、秘密配置及不同导出格式的范围仍需分别核对，见[备份范围](PRIVACY.md#备份不是全量镜像)。

## 隐私室恢复密码

- 人类可新建带恢复密码的房间，或在本机仍能打开的既有房间设置/修改密码；密码支持 8–128 个 UTF-16 字符，保留中文、符号和空格，不自动裁剪或规范化。
- 密码用于 PBKDF2-HMAC-SHA256（600,000 次迭代）派生包裹密钥，配合随机盐及 AES-GCM；不保存明文密码，也不将恢复密码交给 AI 配置工具。恢复或导入先校验记录，再提交数据。
- 保留旧随机恢复码和 v1 备份兼容。带密码的 v2 包可另签发备用随机码；旧版客户端不能把新格式当作旧格式回写。没有本机可用密钥时，不能用“设置新密码”绕过原恢复凭据或生成空房间冒充恢复。
- 修改恢复密码不改变助手身份、现有房间内容或既有分享许可，也不撤销已经导出的旧备份所用凭据。请重新导出新版备份，并分别妥善保管旧备份所需的凭据。

## 导入、消息输入、通知和用量

- Kelivo 聊天导入支持明确的 v2/v3 容器与对应数据库结构；先预览、选择，再追加提交。未知 v4 仍拒绝，不导入其配置、密钥、人格或权限，不执行历史工具。附件继续按导入器的占位范围处理，不宣称复制了所有实体文件。
- 修复旧暂停队列挡住新颜文字或贴纸发送的路径；真实录音、当前通话、未完成工具和正在编辑等状态仍正确区分。
- 通知按事件隔离错误，某次通知或清理失败不再导致后续订阅全部停止；不重新发送旧通知。
- 用量合并区分“没有报告缓存命中”与“明确报告为零”，防止继承上次的命中量；保持旧恢复记录默认字段编码兼容。用量显示修复不代表服务商账单或缓存策略发生变化。

## 必须保留的已知限制

1. **附件累积 HTTP 413 尚未修复。** 长窗口的历史图片等附件可能使实际请求过大，随后发送纯文字仍可能携带这些历史附件。完整发送预算与降载处理不在本版完成范围内；不要将清理附件当作无损缓存操作，删除本地原件可能导致历史附件不能再发送。
2. **慢链路大型备份仍会超时。** 当前一次自动备份有八分钟期限，大存档在低速上传时可能在远端发布前超时并重试；旧固定存档保留。不能只因任务启动就声称云端已更新，也不能保证一键恢复的是尚未成功上传的新数据。
3. **自定义请求头作用范围仍需修正与复核。** 本版没有完成不同服务和请求之间的作用域修复，不把配置可填写等同于作用范围已经正确。
4. 网络上传缓慢、等待响应头超时、后台限制及设备差异仍可能造成等待或通话/通知异常。此次修复的是已确认代码缺口，不宣称所有历史异常已有唯一根因或全部消失。
5. 未做真实用户卸载后全量回拉验证；没有保存过、没有成功备份过的数据不可凭空恢复。恢复密码、普通聊天 ZIP 与完整应用数据保全是不同范围。
6. 随附 ONNX Runtime 1.20.0 的 Java JNI 库仍为 4 KiB ELF 页对齐；16 KiB 页大小设备上的可选离线语义召回未验收，可能不可用。召回路径对链接失败作空结果降级，但这不等于整机功能已保证兼容。ZIP 对齐校验与这一限制不同，见[原生来源和核对范围](OFFLINE-MEMORY-SOURCES.md)。

## 安装、包名及回退

- 日常使用 `Orbis-2.6.12-…apk` 主包。`OrbisRescue-2.6.12-…apk` 是按需覆盖的备份入口包；主包不含紧急入口或自我修复，正常备份保留。两者同包名、同签名，不是两个可独立卸载的应用，也不是插件。详见[主包与 Rescue 说明](NO-RESCUE-BUILD.md)。
- 正式版包名为 `org.orbis.agent`，Dev 为 `org.orbis.agent.dev`；二者数据独立，正式版不会覆盖 Dev 或自动迁移其数据。不要为切换包名先卸载仍需保留数据的应用。
- 最低 Android 8.0；提供 `arm64-v8a`、`x86_64` 和包含这两种架构的 `universal`，不包含 32 位 ARM。源码 ZIP 不是 APK。
- 只对来源、签名和版本均符合要求的同包 APK 覆盖安装，不清数据、不通过卸载绕过签名冲突。schema 30 及隐私室 v2 不能被当作旧版可无条件读取；回退前核对[更新与回退边界](UPDATES-AND-ROLLBACK.md)。
