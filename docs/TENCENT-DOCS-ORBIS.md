# 腾讯文档接入 Orbis：群管与 AI 协作填表教程

核验日期：2026-11-15。适用于腾讯文档的普通「在线表格」（工具前缀 `sheet.*`）。

接好后，你可以让自己的 AI 读取共享登记表、核对重复申请，再按你的安排填写指定单元格。人类继续使用表格里的下拉菜单；AI 写入同一个选项文字，两边操作的是同一份云端表格。

这里接的是**腾讯文档官方 MCP**。不需要购买 VPS、开通腾讯云服务器，也不需要腾讯云 SecretId / SecretKey。模型与 ST 的原有连接可以保留。

- **群管先做：**取得表格编辑权限 → 获取自己的腾讯文档 Token → 添加 Orbis MCP → 选给自己的 AI → 只读验收。
- **给 AI 的完整交接：**[腾讯文档填表协作指令](TENCENT-DOCS-AI-HANDOFF.md)。可以把该文件链接发给 AI，再私下提供表格链接与本次名单。
- **下拉选项说明：**见本文第 6 节；普通读格工具不返回选项全集，不能凭空推断。

## 1. 开始前准备

1. **Orbis 版本。**本教程的手机连接已在包含腾讯 MCP 工具名兼容修复的版本验证。群内测试版请使用 **2.6.19-rc.20 或更新的同系列测试包**；本次核对的最新版测试包为 rc.23。旧版若调用带点号的工具名时报 HTTP 400，应升级兼容版本。本文发布不代表 GitHub Releases 同时发布了这些测试包；安装包以管理方提供的正式渠道为准。
2. **自己的腾讯文档账号。**可以在浏览器打开目标表格。表格所有者需要将这个账号加入可编辑协作者；只有查看链接不等于有编辑权限。
3. **支持工具调用的模型连接。**你原本经过 ST 的聊天连接可以继续使用；腾讯文档作为 Orbis 的独立 MCP 工具连接，不需要把 Token 填到 ST 的模型 API Key 里。
4. **本次工作范围。**例如“登记这 3 位申请人”，或“把指定申请的审核结果改为已通过”。登记、审核、分配邀请码、发邮件是不同动作，分别按实际授权执行。

每位群管用自己的账号和 Token。不要共用开发者或其他群管的 Token。共享表格的真实链接、账号、邮箱、邀请码等资料由管理方私下提供，本公开教程不包含这些内容。

## 2. 获取腾讯文档授权

1. 打开[腾讯文档官方 MCP 授权页](https://docs.qq.com/open/auth/mcp.html)。
2. 登录**有目标表格编辑权限的那个账号**，按页面指引取得个人 Token。
3. 将 Token 直接粘贴到下一节的 Orbis 请求头值中。不要发进普通聊天、群消息、公开问题区或带凭据的截图。

腾讯文档官方当前配置使用 `Authorization` 作为请求头名称，值直接填写 Token。**不要照着 Orbis 输入框里的通用示例擅自加上 `Bearer `。**官方配置与授权页面见[腾讯文档团队的接入说明](https://developer.cloud.tencent.com/mcp/server/11803)；若服务今后调整，以重新生成的官方配置为准。

Token 属于登录账号的授权，不是单张表的密码。即使 AI 只负责一张登记表，也应明确限制任务范围。读出的表格内容会进入当前模型的处理链路，请只提供完成任务所需的数据。

## 3. 在 Orbis 添加 MCP

### 3.1 手动填写（推荐）

从当前 AI 的聊天进入「系统设置」→「MCP 与工具」→「添加、导入与高级管理」，点击添加。不同版本入口排版可能略有区别，最终进入的页面标题是「MCP」。

在「基础设置」填写：

| 设置项 | 填什么 |
| --- | --- |
| 启用 | 开启 |
| 名称 | `TencentDocs`，使用英文字母或数字 |
| 显示名称（如有） | `腾讯文档` 或便于自己辨认的中文名 |
| 传输类型 | **Streamable HTTP** |
| 服务器地址 | `https://docs.qq.com/openapi/mcp` |
| 自定义请求头 → 请求头名称 | `Authorization` |
| 自定义请求头 → 请求头值 | 从腾讯官方页面复制的完整 Token |

保存后等待连接与工具目录加载。第一次添加时不能查看工具目录，保存后重新打开该服务的「工具」页即可查看。

这里不要填写表格的分享网址，也不要选择 SSE。MCP 服务器地址和表格链接承担不同用途。

### 3.2 JSON 导入（可选，与手动添加二选一）

Orbis 的「导入 MCP 服务器」支持以下标准结构。在**本机配置编辑器**替换占位符后导入，不要把带真实 Token 的 JSON 发给 AI 或其他人：

```json
{
  "mcpServers": {
    "TencentDocs": {
      "type": "streamable_http",
      "url": "https://docs.qq.com/openapi/mcp",
      "headers": {
        "Authorization": "在本机替换为你自己的腾讯文档Token"
      }
    }
  }
}
```

占位符不能连接成功。已手动添加过就不要再导入一份；如果要替换授权，在已有服务中修改。

### 3.3 选择工具

对普通登记表，先启用以下 7 项即可：

| 腾讯原始工具名 | 用途 |
| --- | --- |
| `manage.search_file` | 按标题寻找文档 |
| `manage.query_file_info` | 核对文档名称、类型、链接等信息 |
| `manage.get_privilege` | 查看文档的共享策略 |
| `sheet.get_sheet_info` | 获取子表名称、ID、尺寸 |
| `sheet.get_cell_data` | 读取表头、内容、公式 |
| `sheet.set_cell_value` | 写指定单元格 |
| `sheet.set_range_value` | 批量写指定单元格列表 |

写入工具可打开「需要审批」，让人类核对本次落点；只读工具按需开放。删除文档、修改共享权限、重建工作表等工具不属于日常登记必需项。

`manage.get_privilege` 的 policy 是共享策略，**不等于当前账号的完整有效权限报告**。例如私密文档的所有者也可以编辑；不要仅凭 policy 的数字判断自己一定能写或不能写。

## 4. 把服务选给正确的 AI

回到「系统设置」→「MCP 与工具」→「管理当前 AI 的选用」，确认页面显示的是你要协作的 AI，再选中 `TencentDocs`。也可以从该助手的设置进入 MCP 选用页。

需要同时满足：

1. 全局服务已启用且已连接。
2. 需要的工具已启用。
3. 当前助手已经选用这个服务，相关工具没有被当前助手的边界设置隐藏或暂停。

“服务已连接”只证明连接层状态。最终以**这个 AI 在实际聊天中成功调用工具**为准。

把这段话和管理方私下提供的表格链接发给 AI：

> 请检查你实际可用的腾讯文档工具，只读连接验收。目标是我提供的共享表格。先确认文档与子表，再读「填写说明」及「申请登记」表头，告诉我看到了哪些字段。不要填写真实申请、修改公式、发放邀请码或发邮件。若调用失败，请给出脱敏后的工具名、参数结构、错误码和 trace_id，不要索要或回显 Token。

### 表格链接、file_id、sheet_id 怎么区分

- **分享链接**供浏览器打开整份文档。
- **`file_id`**是工具使用的文档标识。优先使用工具返回的 ID，或管理方确认过的 ID；不要直接把分享链接最后一段当作已验证的 `file_id`。
- **`sheet_id`**是文档里的子表 ID，必须调用 `sheet.get_sheet_info` 获取；“申请登记”是子表名称，不是 ID。

只知道链接时，可先按准确标题搜索，再核对返回链接、名称和创建人等信息。找不到就请管理方提供已验证的 ID。**搜索 0 条并不能证明 Token 失效**，也不能用搜索文档标题的接口去搜 ID。

## 5. 日常登记怎么做

群管可以这样给任务：

> 请登记我下面明确提供的 3 位申请人。先读当前表头、填写说明、下拉选项约定，并核对账号和邮箱是否重复。使用我们约定的空行范围，仅填写手工列。初始审核状态为「待审核」，发信状态为「待发送」，注册状态为「未核验」；邀请码先留空。缺失资料列出给我，不猜。写完逐格读回并告诉我申请编号和行号。此任务不包括发码和发邮件。

AI 应按以下顺序执行：

1. 读取最新填写说明、列名和必要范围，不把旧记忆中的列位置当现场。
2. 按账号和邮箱查重。比较时可以统一大小写、空格；保留用户提交的原始账号，QQ / 微信号按文本写入，前导 `0` 不能丢。
3. 重复项提示人类核对，不删除原记录，也不把同名账号直接认定为违规。
4. 和其他群管约定本次负责的行范围或批次，写入前再读目标行，发现已有人填就停止占用该行。
5. 只写明确授权的手工字段，写后重新读取实际值。
6. 报告成功、未填和需核对项。请求超时先读回，不能直接换一行重写，造成重复登记。

当前邀请登记模板的字段如下。管理员调整列后，以实际表头为准：

| 列 | 内容 | AI 处理方式 |
| --- | --- | --- |
| A | 申请编号 | 按管理方编号规则填写，不能假设连续编号由工具保证 |
| B | QQ号 / 微信号 | **文本**，保留字母和前导零 |
| C–D | 收件邮箱、群内昵称 | 按明确提供的资料填写 |
| E | 来源群 | 目前下拉为 `QQ` / `微信`；具体群名如需记录，按管理方约定写备注 |
| F–G | 经办群管、登记时间 | 填实际经办人和管理方约定时区的时间；G 已有日期校验 |
| H | 审核状态 | 使用允许的下拉选项，未审核不能直接标通过 |
| I–J | 账号查重、邮箱查重 | **自动公式，不覆盖** |
| K | 对应邀请码 | 只有获得具体发码授权和真实码后填写 |
| L–N | 发信状态、发信时间、邮件回执ID | 根据实际发送结果填写，不能凭“准备发送”标成功 |
| O | 注册状态 | 根据实际核验结果填写 |
| P | 备注 | 补充必要的经办信息 |
| Q–R | 标准账号、标准邮箱 | **隐藏的自动公式，不覆盖** |

模板预置公式覆盖到第 2001 行。不要认为第 2002 行起会自动延续查重与下拉规则；接近容量时请管理方安排扩展。

多个 AI 都能“先读空行再写”，仍可能同时选中同一行。这些普通写格接口没有在本教程中验证原子抢占能力；约定分工或由一个登记人统一排队，比把空行当锁可靠。也不要因表内已存在公式，就把整行判为“有人填了”：应检查手工字段。

## 6. 下拉框，AI 能不能用？

**本次核验的普通在线表格可以。**AI 通过写格工具写入选项原文，不需要模拟点击网页下拉箭头。

2026-11-15 核对到的当前选项：

| 字段 | 允许的非空选项 |
| --- | --- |
| 来源群 | `QQ`、`微信` |
| 审核状态 | `待审核`、`已通过`、`需核对`、`不予发放`、`已取消` |
| 发信状态 | `待发送`、`已发送`、`发送失败`、`结果待核验` |
| 注册状态 | `未核验`、`未使用`、`已使用`、`已停用` |

比如选项是「已通过」，就写「已通过」，不要自造「审核通过」。来源群现在只有「QQ／微信」，不要直接写一个不在选项里的群名。选项可能由管理员修改，这张表是核验日的快照。

### 怎样让 AI 知道管理员新增了选项

`sheet.get_cell_data` 返回单元格内容与可选的公式，**当前工具返回结构没有下拉规则字段**。看到某格写着「待审核」，只能确认这个值，不能推断全部可选项。

最方便的做法：管理员改下拉时，把「列名 → 可选文字」同步写进共享文档的「填写说明」，让 AI 每次先读。也可以把准确选项私下发给 AI。

有文件处理能力的管理 AI，可在获准后通过 `manage.export_file` 与 `manage.export_progress` 导出 XLSX，检查数据验证规则。轮询同一 task_id，完成后在本机下载；临时签名下载链接不要公开。读到引用区域或命名范围时，要继续解析其来源，不能把所有下拉都当逗号分隔字符串。

登记工具的 7 项权限不包含导出，**不需要为了日常填表给所有 AI 开放更多管理工具**。无法读取规则时，询问管理员即可。

### 本次实际验证了什么

- 从现有表格生成仅本人可见的临时副本，正式共享表未写入测试数据。
- 使用真实腾讯文档 MCP 的单格与批量写入，覆盖四个下拉字段的全部 **15 个非空选项**，逐项读回一致。
- 写入后导出核对：四组下拉规则与一组日期校验均保留，**8,000 个公式的文本及属性均未改变**。
- 文本账号的前导零保留。日期 `2026-11-15` 以文本写入并读回成功；这不代表验证过日期控件显示、全部日期类型或后续按日期统计。
- 临时测试副本在核验后移入回收站。

这验证的是当前普通在线表格的已有单选列表。**没有验证智能表格的多选字段、级联下拉，或任意无效值都会被服务端拒绝。**AI 应先校验选项，再写入，不把 API 成功当作业务审核通过。

其他助手已经真实通过手机模型链路的只读调用；本次下拉写入由维护者实际执行，没有冒用其他 AI 身份。群管自己的 AI 仍应完成第 4 节只读验收，首次写入用授权的测试表或测试行。

## 7. 给 AI 和技术人员的调用例子

以下使用腾讯原始工具名。Orbis 暴露给模型时可能加前缀或转换为安全别名，**请调用实际工具列表里的名字**，不要拼一个不存在的工具名。参数使用 JSON 对象；服务定义变动时以当前参数说明为准。

### 7.1 先获取子表

`sheet.get_sheet_info`：

```json
{"file_id":"由管理方提供并核对的文档ID"}
```

从返回结果找到目标子表的 `sheet_id`，再读表头。普通表格的行列索引从 0 开始；本次实测 `get_cell_data` 的结束索引也包含在读取范围内。

例如只读第 1 行的 A:R：`sheet.get_cell_data`：

```json
{
  "file_id": "已核对的文档ID",
  "sheet_id": "工具返回的子表ID",
  "start_row": 0,
  "end_row": 0,
  "start_col": 0,
  "end_col": 17,
  "return_csv": false,
  "include_formula": true
}
```

注意：空格子可能不出现在返回的 `cells` 中；按返回的 `row` / `col` 定位，不按数组第几个元素猜列。某格的 `value_type` 可能是计算结果类型，但仍带 `formula`；有公式就按公式格保护。

### 7.2 写一个下拉值

**仅用于管理方授权的测试表／测试行。**示例把 H2 写成「待审核」，不代表授权覆盖真实 H2。

`sheet.set_cell_value`：

```json
{
  "file_id": "已核对的测试文档ID",
  "sheet_id": "工具返回的子表ID",
  "row": 1,
  "col": 7,
  "value_type": "STRING",
  "string_value": "待审核"
}
```

写入后，用 `sheet.get_cell_data` 读取同一格，确认实际内容。

### 7.3 批量填写时跳过公式列

`sheet.set_range_value` 的 `values` 是单元格列表，可以只列出本次要改的格子；不必提交整行，也不要用空字符串占位覆盖 I/J/Q/R。

下面仅演示测试表 B2、E2、H2，账号为合成示例：

```json
{
  "file_id": "已核对的测试文档ID",
  "sheet_id": "工具返回的子表ID",
  "values": [
    {"row": 1, "col": 1, "value_type": "STRING", "string_value": "001234560"},
    {"row": 1, "col": 4, "value_type": "STRING", "string_value": "QQ"},
    {"row": 1, "col": 7, "value_type": "STRING", "string_value": "待审核"}
  ]
}
```

## 8. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 连接成功，AI 说没有工具 | 是否选给当前 AI、单项工具是否启用、是否被助手边界隐藏／暂停；回原聊天发起一次新的只读请求 |
| HTTP 400，涉及工具名字符 | 检查 Orbis 是否包含腾讯点号工具名兼容修复；模型服务也须支持工具调用；不要先反复换 Token |
| 鉴权失败、400006 | 请求头必须叫 `Authorization`，值无多余换行／引号／擅加的 Bearer；在官方页面检查或重新取得授权 |
| 400007 或权益不足 | 腾讯账号权益限制；先确认账号与官方页面说明，不自动购买、不承诺所有账号免费可用 |
| 搜索 0 条 | 搜索通常按标题；核对账号、准确标题，或使用管理方验证过的 file_id |
| 能读不能写 | 核对当前账号编辑权限、保护区域与写入审批；不要为了排错改成全网可编辑 |
| 读到别的子表／写错列 | 重新取 sheet_id 和表头；索引从 0 开始；先用单格检查 |
| 新下拉选项不知道怎么填 | 读最新填写说明，向管理员确认选项，或授权导出后检查；不要靠历史值推测全集 |
| 日期写入不合适 | 核对该列的日期规则、时区与格式；文本可读回不等于日期控件／计算均兼容 |
| 写入超时或回复丢失 | 先读回原位置，确认实际结果；记录脱敏的 trace_id，不盲目重试或新增一行 |

“已发送”不代表对方已收到邮件或已注册；“已通过”也不代表已经分配邀请码。普通腾讯文档工具负责表格，不自动提供邮箱发信或邀请码管理能力。

## 9. 给群管的交付检查

完成后应能回答这四项：

1. 我的腾讯账号有目标表格的编辑权限吗？
2. Orbis 服务已连接，而且正确的 AI 已选用吗？
3. AI 在实际聊天中读到的是正确文档、子表与表头吗？
