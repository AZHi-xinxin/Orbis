retain their original Artifex copyright and AGPL-3.0-or-later notices.
For example, fitz/Context.java states:
Copyright (C) 2004-2021 Artifex Software, Inc.
MuPDF project and license information:
https://github.com/ArtifexSoftware/mupdf
https://github.com/ArtifexSoftware/mupdf/blob/master/COPYING
The binary contains the version identifier 1.26.8. The corresponding
official versioned source and Android build project are:
https://github.com/ArtifexSoftware/mupdf/tree/c1b5d46e70512666b8695fb31ff280be0eff2469
https://github.com/ArtifexSoftware/mupdf-android-fitz/tree/0c15358b3ef0b45cd03baab47079d94447018d9f

NDK 28.2.13676358. MuPDF-1.26.8-COPYING.txt contains its AGPL-3.0 text.

all 17 pinned MuPDF third-party submodule source archives, retaining
their own licenses. See the source tree's third_party/native-build-references
for the complete pinned source map and original build references.

Simple SQLite extension and PRoot
--------------------------------
libsimple is loaded as a SQLite extension. Its exported symbols identify
Simple and cppjieba. Simple's original dual MIT/GPL-3.0-or-later license
is preserved in Simple-LICENSE.txt; Orbis uses the MIT option. The
cppjieba MIT license is also included. A pinned upstream source snapshot
is supplied for reference, not claimed as the exact historical build
revision of these inherited Simple binaries.

libproot_exec and libproot_loader are used by the workspace shell runner.
The executable contains version 5.1.107.92. Its source is:
https://github.com/termux/proot/tree/7266fb3e8516535682f5a9c8f3a7e70f6506eddb
PRoot source headers grant GPL-2.0-or-later; the original COPYING text
is preserved in PRoot-5.1.107.92-COPYING.txt.

The RikkaHub organization publishes its Android build and extraction
workflow, which produces libproot_exec.so and libproot_loader.so for
arm64-v8a and x86_64:
https://github.com/rikkahub/termux-packages/tree/d9f8efa3a3e9c368a06546b1bf64d094d46c54ad
The recipe statically links talloc 2.4.3 and libandroid-shmem 0.7.
Their original LGPL-3.0 and BSD-3-Clause texts are included here.
The official dependency sources and checksums are included in the source
map and release native-source index, together with the build recipe.

Release boundary
----------------
Exact equality with the RikkaHub snapshot proves unchanged inheritance.
Version identifiers, pinned official source and build recipes provide a
rebuild/source-availability path, not a claim of a byte-reproducible build
audit. APK releases must retain the source package and the native-sources
companion archive (or equivalent accessible complete source), including
applicable dependency notices. The Simple source revision remains a
reference snapshot rather than a proven exact historical revision.
